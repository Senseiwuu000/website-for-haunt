        03 / know ratters

        People who ship rats.

        A RAT is a remote access trojan — it hands someone else your files, sessions or screen. This list exists so you can check a name before you run their build. Every row needs a reason and a piece of evidence. No evidence, no row.

        04 / faq

        Fair questions.

        The ones that come up every week, answered without a sales voice.

        Do you rat people?

        No. There is no analytics, no cookie, no upload endpoint and no account system on this page. The scanner is plain JavaScript, starting at scanner.js, and you can read every line of it. Every listed build gets its SHA-256 published so the exact file you downloaded can be checked by someone who is not us.

        If a listing's hash does not match the file you got, do not run it. That is how a swapped build looks.

        Does the scanner upload my jar?

        No. The file is read with the browser's File API, unzipped in memory and thrown away when you close the tab. Open dev tools and watch the network tab while a scan runs if you want to be sure. The one thing the page downloads is its own code.

        Why is there a 200 MB limit?

        Because the scan happens in your browser's memory, not on a machine with 32 GB to spare. 200 MB covers every client and menu on the shelf. Bigger archives can go through #tickets and get looked at by hand.

        What does the scanner actually check?

        Manifest entries (including Premain-Class and Agent-Class), jar signatures, embedded executables and native libraries, double extensions, nested jars, and the string constants in every class: process spawning, shell commands, Discord webhooks, download calls, reflection loaders, persistence paths, credential paths, screen capture and key input. On top of that it looks at class-name obfuscation and pulls out every URL in the build.

        It is a static, rule-based scan. "Nothing obvious" means nothing matched, not that the file is safe. A clean report and a VM is the sane combination.

        Do you decompile jars for people?

        Yes, in #tickets. Vineflower first, Recaf for quick passes, Fernflower when Vineflower trips on an old class. Paste the SHA-256 from the scan report so the file you have and the file being pulled apart are provably the same one. Turnaround depends on the queue and on how badly the build is obfuscated.

        Are the listed clients safe?

        They are checked, not blessed. Every build gets the same scan and the report is published, but a rule-based scan cannot prove intent, and clean code can still get your account banned. Run this stuff on a spare machine or a VM, never on an account you care about.

        How do I report a build or get removed from the list?

        Open a ticket with the hash, the source and what you found. If a row is wrong, it gets corrected with a visible note. If you are on the list and you have proof the row is wrong, that gets published too — being fast is not worth being wrong.
